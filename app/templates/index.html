01 / ATTACK SURFACE

Domain Trust.

Review public DNS records, email authentication, HTTPS response headers, and TLS validity for domains you are authorized to assess.

Start a domain posture check

A few read-only DNS queries and a single HTTPS HEAD request.

WHAT WE INSPECT

Trust signals, not exploits.

  • SPF and DMARC policy presence
  • CAA and DNSSEC DS observations
  • TLS hostname/certificate validation
  • Browser security headers
  • Priority recommendations and risk score

Private networks and reserved IP targets are blocked. Requests do not follow redirects.

05 / VULNERABILITY LIFECYCLE

Vuln Priority.

Rank an existing scanner export by real-world risk — exploitation evidence, exposure and business criticality — instead of CVSS alone.

Prioritize a scanner export

CSV or JSON with cve, asset, cvss; optional epss, kev, internet_exposed, asset_criticality, first_seen.

DECISION RULES

Explainable, SLA-driven.

  • P1 · 7 days: CISA KEV on exposed or critical asset; EPSS ≥ 0.5 + CVSS ≥ 7 + exposed
  • P2 · 30 days: KEV, or likely (EPSS ≥ 0.1) and CVSS ≥ 7, or CVSS ≥ 9 on an exposed or crown-jewel asset
  • P3 · 90 days / P4 · 180 days: batched for patch cycles
  • Overdue flag from first_seen + SLA
  • Optional offline enrichment: scripts/enrich_vulns.py

08 / EVIDENCE INTEGRITY

Evidence Vault.

Record cryptographic fingerprints and metadata for consented artifacts. Files are hashed in memory and not retained.

Register a file fingerprint

SHA-256 hashes for lightweight evidence provenance.

INTEGRITY MODEL

Verify, without collecting.

  • SHA-256 digest with file size and timestamp
  • Append-only-in-practice audit hash chain
  • Local SQLite metadata persistence
  • No archived copies of uploaded files

A hash chain alone is not tamper-proof against someone who can rewrite the database. Back up or externally anchor audit digests for stronger assurance.
